# 조각 HTML 작성 규칙 (fragment-spec)

병렬 에이전트에게 화면 조각 작성을 맡길 때 이 문서를 프롬프트에 그대로 붙인다. `<담당 화면>`, `<출력 파일>`, `<원본 md>`, `<디자인 기준 문서>`만 바꾼다.

---

담당 화면: <담당 화면>. 출력 파일 하나: <출력 파일> (frag_X.html, 이 파일만 쓴다. 다른 파일·프로젝트 파일 수정 금지).

1. 입력: <원본 md>에서 담당 화면의 `### SCR-XXX.` 섹션(메타 표, ASCII 레이아웃, UI 컴포넌트 표, 상태별 화면, 처리 규칙)을 읽는다. 공통 컴포넌트는 같은 문서의 공통 컴포넌트 장을 참고한다. 스타일 규칙은 <디자인 기준 문서>를 따른다.
2. 참고 구현: `<sb-lowfi-pptx 스킬 폴더>/assets/lowfi.css`(공통 CSS, 수정 금지, 클래스 목록은 파일을 읽어 파악)와 `assets/example_fragment.html`(완성 예시, 구조와 문법을 그대로 따른다). 새 스타일은 인라인 style만 쓴다(`<style>` 태그 금지).
3. 출력 형식: 화면마다 `<div id="scr-nnn" class="screen-section">` 한 개(소문자 id). 안에 순서대로:
   - `<h2>SCR-NNN 화면명</h2>`
   - `<div class="meta">URL · 플랫폼 · 접근권한 · 관련 기능 · API</div>`
   - 와이어프레임: `<div class="row">` 안에 프레임. 프레임마다 `<div><p class="cap">캡션</p><div class="pc">…</div></div>` 또는 `.mo`. 반응형 화면은 PC와 모바일 둘 다, 관리자 등 PC 전용 화면은 `.pc` 한 가지. 캡션은 PPTX에서 프레임 제목으로 쓰이므로 "기본", "오류 / 빈 상태"처럼 상태를 적는다.
   - 컴포넌트 설명표: `<div class="spec"><table>` (No. / 컴포넌트 / 설명·인터랙션, 첫 열 `<b>번호</b>`, 범위는 `8~10`)
   - 상태별 화면: `<div class="stbl"><h4>상태별 화면</h4><table>` (상태 / 조건 / 표시 내용)
   - 처리 규칙: `<div class="stbl"><h4>처리 규칙</h4><ul><li>…`
   - `<html>`/`<body>` 없이 section div들만.
4. 번호 마커: 요소에 `data-n="번호"`를 붙이면 주황 원이 표시된다. 번호는 문서 UI 컴포넌트 표 번호와 정확히 일치해야 하고 표의 번호는 전부 한 번 이상 화면에 붙인다. 겹침 방지:
   - 글자·링크·제목 같은 텍스트형 요소는 `class="t|hd|s|link|m|lbl"` 중 하나를 달고 data-n을 붙인다(마커가 글자 왼쪽 여백에 놓임).
   - 박스형(`.card`, `.btn`, `.badge`, `.seg`, 입력칸 등)은 좌상단 모서리에 놓이므로 바로 위·왼쪽 10px 안에 다른 글자가 없게 간격을 둔다.
   - 한 줄에 마커가 이어지면 gap 12px 이상.
   - `overflow:hidden` 요소 안의 마커는 잘리므로 바깥 래퍼에 붙인다.
   - PC와 모바일 프레임 모두 기본 화면에는 마커를 붙인다(한쪽만 붙이지 않는다). 마커는 반드시 해당 번호의 컴포넌트 요소 자체에 붙인다. 설명표에 없는 요소에 번호를 붙이지 않는다.
   - 상태 프레임(오류·빈 상태·모달)은 그 상태에서 새로 나타나는 요소에만 번호를 붙인다(PPTX 빌드 시 글자가 같은 요소에는 번호가 자동으로 옮겨 붙는다).
5. low-fi 규칙: 회색 계열, 긴 본문은 `<div class="ln"></div>` 회색 줄, 제목·버튼 문구는 실제 샘플 문구. 상태 표시는 색만 쓰지 말고 `[정답]` `[경고]` `[오류]` `[안내]` 같은 문구와 기호를 함께 쓴다. 핵심 상태가 레이아웃을 크게 바꾸면(빈 상태, 오류, 모달, 로딩) 추가 프레임 1~2개로 그린다(`.modal`). 나머지 상태는 표로만 둔다. PC 프레임 폭은 1000px, 모바일은 375px로 고정한다(PPTX 고정 축척 기준). 높이가 PC 860px, 모바일 780px를 넘으면 PPTX에서 자동 분할되므로 의미 단위로 나누고 싶으면 미리 프레임을 나눈다.
6. 검증: 임시 HTML(`<!doctype html><meta charset=utf-8><style>lowfi.css</style>` + 조각)을 만들어 헤드리스 Chrome으로 스크린샷을 찍어 확인한다.
   `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --window-size=1300,<높이> --screenshot=<png> file://<경로>`
   긴 이미지는 `sips -c <높이> 1300 --cropOffset <y> 0 in.png --out out.png`로 잘라 본다(macOS에 timeout 명령 없음). 문서의 컴포넌트 번호 집합과 HTML data-n 집합이 같은지 파이썬 정규식으로 점검한다.
7. 이모지 금지. 완료 보고는 3줄 이내(만든 화면 id, 문서와 달리 임의로 정한 사항, 남은 문제).
